# 커밋 이력 동기화 (IDX-3-01)

2026-11-10 (Asia/Seoul), S15P31D108-185. 브로커가 바인딩된 프로젝트의 커밋 이력을 중앙에 올린다. 담당 Agent 탐색(FIND-3-01)은 이 이력으로 "최근 수정" 근거를 계산한다. 업로드 본문은 [Git 수집 범위 제한](git-collection-scope.md)의 `CommitBatch`로 만들고, 작성자는 [Git 이메일 판별](git-identity.md)의 `IdentityCache`로 정한다.

## 동작

- 브로커가 시작될 때 바인딩된 Agent 프로필이 있으면 동기화를 시작한다. `gitCollection`이 `false`이면 작업 파일 수집과 함께 시작하지 않는다(기본 `true`). 원격·저장소 키 규칙은 [작업 파일 수집](working-files.md)과 같다(`dependencyRemote`, 비어 있으면 `origin`). Git 저장소가 아니거나 원격을 찾지 못하면 한 번 알리고 동기화하지 않는다.
- 시작 직후, 이후 60초마다 `HEAD`에서 도달하는 병합 제외 커밋 중 마지막 체크포인트 이후의 범위를 정한다. 체크포인트의 `HEAD`·작성자 판별 기준·shallow 경계가 모두 같으면 보내지 않는다.
- 커밋 시각이 최근 90일 안인 커밋만 보낸다. 중앙 추천이 최근 90일 커밋만 쓰기 때문이다(`RecommendationScorePolicy.COMMIT_WINDOW`). 개수 제한은 없다. 범위 안의 커밋은 첫 동기화든 이후 동기화든 모두 보낸다.
- 범위는 `git rev-list --timestamp --no-merges --topo-order --reverse`로 오래된 순서대로 순회한다. 출력은 한 줄씩 읽고 committer 시각이 최근 90일인 SHA만 로컬에서 남긴다. Git 2.37 미만에서도 같은 명령을 쓰며 `--since`로 순회를 조기에 끊지 않는다. 그래서 시계가 틀린 PC에서 만든 오래된 시각의 커밋 앞에 있는 최근 조상도 수집한다. 선택한 SHA는 1,000개씩 묶어 `git log --no-walk --name-status -z`로 파일 목록을 읽는다.
- 파일 목록은 사용자 Git 설정과 관계없이 같아야 한다. 중앙은 같은 SHA에 다른 파일 목록이 오면 `COMMIT_CONTENT_MISMATCH`로 거부하기 때문이다. 그래서 다음을 고정한다.
  - 루트 커밋의 파일 표시(`--root`, `log.showRoot` 무시)
  - 내용이 같은 파일의 이름 변경 탐지(`-M100%`, `--rename-empty`). 내용까지 바뀐 이름 변경은 삭제·추가로 기록한다. blobless 클론에서도 blob 다운로드 없이 같은 파일 목록을 만든다.
  - 서브모듈 포인터 변경 표시(`--ignore-submodules=none`, 사용자 ignore 설정 무시)
  - 경로 인용 해제(`core.quotePath=false`)
  - 외부 diff·서명 표시 끔
- `POST /api/v1/teams/{teamId}/git/commits:batch`로 보낸다. 배치는 커밋 100개, 본문 128KiB 이하다. 배치마다 중앙 연결 상태(Connected, 신원 일치)를 다시 확인한다.
- `tree:` 필터로 받은 클론(트리리스 클론)은 파일 목록을 읽기 전에 묶음의 커밋과 부모 커밋 중 없는 루트 트리를 promisor 원격에서 미리 받는다. `git fetch --filter=blob:none --stdin`으로 트리 200개씩 한 번에 요청하며(요청당 60초 제한), 하위 트리는 함께 오고 파일 내용은 받지 않는다. 이렇게 하지 않으면 Git이 트리를 커밋마다 따로 받아 15초 제한 안에 끝나지 않는다. 미리 받기가 실패해도 파일 목록을 읽는 동안 Git이 남은 트리를 가져오고, 그마저 실패하면 해당 묶음의 체크포인트를 전진시키지 않고 다음 동기화에 재시도한다. 원격 접근은 이 두 단계에서만 허용하며 자격 증명 입력 창은 띄우지 않는다.
- `git rev-parse --git-path shallow`의 경계 커밋은 부모와 비교할 수 있을 때까지 전송을 보류한다. 이력을 더 받으면 경계 지문이 바뀌므로 같은 `HEAD`에서도 90일 범위를 다시 수집한다. 수집 중 경계가 바뀐 묶음은 다음 주기에 다시 읽는다.
- 로그는 NUL 필드를 순서대로 해석해 파일명 속 `0x01`·줄바꿈을 보존한다. 경로 검증에서 제어 문자가 있는 파일만 제외한다.

## 체크포인트

- 위치는 프로필 상태 폴더의 `.devlink-runtime/commit-sync.json`(비공개 파일)이다. 스키마 버전, 서버 주소, 팀·사용자 ID, 저장소 키, 커밋 SHA, 작성자 판별 기준, shallow 경계 지문을 담는다. 이전 스키마의 체크포인트는 90일 범위를 다시 수집한다.
- 서버 주소·팀·사용자·저장소 키 중 하나라도 다르면 체크포인트를 쓰지 않고 90일 범위를 처음부터 보낸다. 같은 프로필을 다른 팀이나 서버로 다시 연결해도 새 팀에 이력이 올라간다.
- 1,000개 묶음의 모든 배치가 응답을 받으면 그 묶음의 마지막 커밋을 체크포인트로 저장하고, 범위 전체가 끝나면 `HEAD`를 저장한다. 위상 순서라 어떤 커밋의 조상은 모두 그보다 앞에 오므로, 중간 체크포인트부터 다시 시작해도 빠지는 커밋이 없다.
- 전송 실패, 401·403·5xx 같은 응답, 도중 연결 끊김이면 그 묶음의 체크포인트를 저장하지 않고 다음 주기에 다시 보낸다. 중앙은 팀·저장소·SHA로 중복을 제거한다.
- 400·413은 같은 본문이 다시 거부되므로 그 배치를 건너뛰고 진행한다. 커밋 하나만으로 128KiB를 넘는 경우도 건너뛴다. 중앙이 성공 응답 안에 알린 충돌 커밋도 다시 보내지 않는다.
- Git 파일 목록 출력은 한 번에 16MiB까지만 읽는다. 묶음이 이 한도를 넘으면 두 부분으로 나눠 오래된 쪽부터 읽고 전송하며, 처리한 부분의 파일 목록은 다음 부분을 읽기 전에 해제한다. 단일 커밋만으로도 한도를 넘으면 그 커밋만 건너뛰어 뒤의 정상 이력과 체크포인트 진행을 막지 않는다. 출력 초과 이외의 Git 실행·시간 초과 오류는 건너뛰지 않고 다음 주기에 재시도한다.
- 기록 재작성으로 체크포인트 커밋이 사라지면 90일 범위를 다시 보낸다.
- 이전 수집기가 이미 저장한 잘못된 경로·shallow 경계 목록이나 수정 전 이름 변경 목록과 충돌하면 서버의 `COMMIT_CONTENT_MISMATCH` 정책이 적용된다. 해당 레코드는 운영자가 대상을 확인해 정리한 뒤 프로필 체크포인트를 초기화하고 재수집해야 한다.
- 연속 실패 중에는 stderr에 한 번만 알린다.

## 작성자

- 작성자는 바인딩된 사용자 본인 userId 또는 `null`(미확인)이다. 등록된 Git 이메일과 커밋 작성자 이메일의 해시가 같을 때만 본인이다. 이메일 원문은 보내지 않는다.
- Git 이메일 판별이 아직 오지 않았거나 만료(30초)됐으면 보내지 않고 5초 뒤 다시 확인한다. 판별 전에 보내 본인 커밋이 미확인으로 저장되는 것을 막는다.
- 한 번의 동기화는 시작할 때 받은 판별 결과 하나(`IdentityCache::check`)로 모든 커밋의 작성자와 체크포인트 기준을 정한다. 수집 도중 캐시가 만료되거나 비워져도 본인 커밋이 `null`로 섞이지 않는다.
- 체크포인트에는 범위를 판별한 기준(미등록, 또는 userId·이메일 해시의 지문)을 저장한다. 기준이 바뀌면(이메일 등록·변경) 90일 범위를 다시 보낸다. 중앙은 `null`로 저장한 작성자를 본인 userId로 채운다. 이미 본인으로 저장된 커밋은 바꾸지 않는다.
