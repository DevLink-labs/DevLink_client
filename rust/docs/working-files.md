# 작업 파일 수집 (IDX-3-02)

2026-11-10 (Asia/Seoul), S15P31D108-186. 브로커가 바인딩된 프로젝트의 미커밋 파일 목록을 중앙에 반영한다. 담당 Agent 탐색(FIND-3-01)은 이 관측으로 "작업 중" 근거를 계산한다. 업로드 본문은 [Git 수집 범위 제한](git-collection-scope.md)의 `WorkingFiles`로 만든다.

## 동작

- 브로커가 시작될 때 바인딩된 Agent 프로필이 있으면 수집기를 시작한다. 프로젝트가 Git 저장소가 아니거나, 원격을 찾지 못하거나, 지원하지 않는 원격 형식이면 시작할 때 한 번 알리고 수집하지 않는다.
- 원격은 `dependencyRemote` 설정값을 쓰고, 비어 있으면 `origin`을 쓴다. 저장소 키는 팀 의존성 분석과 같은 규칙(정규화한 원격 URL의 SHA-256)이다. 호스트만 소문자로 바꾸고 경로의 대소문자는 유지한다.
- 30초마다 `git status --porcelain=v1 -z --untracked-files=all --no-renames`를 읽어 `PUT /api/v1/teams/{teamId}/git/working-files/{repoKey}`로 전체 목록을 교체한다. 바뀐 것이 없어도 보낸다. 중앙은 받은 시각부터 90초가 지나면 관측을 만료한다.
- 중앙이 바인딩된 Agent·사용자·팀으로 연결된 상태(Connected, 신원 일치)일 때만 보낸다. 관측 하나가 끝나야 다음 관측을 보내므로 오래된 목록이 새 목록을 덮지 않는다.
- 빈 목록도 관측으로 보낸다. 분리된 HEAD이거나 중앙 규칙(문자·숫자·`._/-`, 255자 이하, `-` 시작·`..` 금지)에 맞지 않는 브랜치 이름은 `branch: null`로 보낸다.
- 중앙 경로 규칙에 맞지 않는 파일 경로는 건너뛴다. 변경 파일이 2,000개를 넘으면 그 주기에는 보내지 않고, 이전 관측은 만료된다.
- 업로드가 실패하면 연속 실패 중 한 번만 stderr에 알리고 다음 주기에 다시 보낸다.

## 탐색 직전 재확인

`find_agent`(`/v1/agents/find`)는 세션 확인 뒤 중앙 추천을 요청하기 전에 작업 파일을 한 번 더 보낸다. 3초 안에 끝나지 않거나 실패해도 탐색은 계속하며, 중앙은 아직 만료되지 않은 기존 관측으로 계산한다. 수집기가 없는 브로커에서는 재확인을 건너뛴다.

## 팀 의존성 분석과의 관계

팀 의존성 분석(client #110)의 3초 주기 임시 전송(`/dependency-graph/working-files/{repoKey}`)은 제거했다. 중앙은 두 경로를 같은 `working_files` 행으로 처리하므로 의존성 트리는 이 수집기의 관측을 그대로 읽는다. 의존성 그래프 업로드(60초)는 `dependencyRemote`가 설정된 경우에만 계속 동작한다.

## 검증

- `cargo test -p devlink-broker --lib working_files`: 실제 Git 저장소와 모의 중앙으로 시작 직후 전체 목록 전송(수정·추가·미추적·삭제), 저장소 키, Agent 토큰, 허용 키만 포함, 정리된 작업 트리의 빈 목록, 재확인 즉시 전송, 다른 사용자로 연결된 동안 미전송, Git 원격이 없는 프로젝트의 수집 생략.
- `cargo test -p devlink-broker --lib dependency_graph::git`: `git status -z` 레코드 해석, 중앙이 거부하는 경로 생략, 2,000개 초과 거부.
